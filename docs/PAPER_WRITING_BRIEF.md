# 论文写作交接简报

这份简报供后续高能力模型开始撰写数学建模竞赛论文时读取。它定义写作阶段需要的证据、顺序和输出边界，不替代具体比赛模板或题目分析报告。

## 开始前的输入检查

写作前确认工作区中存在并已读取：

- `plan.md`：比赛类型、论文语言、排版引擎和子问题数量；
- `reports/ANALYSIS_MODELING_REPORT.md`：模型口径、假设、公式、算法和校验方案；
- `reports/RESULTS_REPORT.md`：实验环境、关键数值、结果表、误差、灵敏度和图表来源；
- `reports/DRAWIO_REPORT.md`（如存在）：非数据图的用途和嵌入建议；
- `figures/`：可引用图片及其真实文件名；
- `skills/5writing/templates/`：匹配语言、比赛和排版引擎的现成模板。

若输入缺失，先补齐前序阶段或记录阻塞原因，再开始写正文。不要用想象中的结果替代缺失输入。

## 写作顺序

1. 根据 `plan.md` 确认语言、比赛和引擎；不确定时向用户确认，默认 LaTeX。
2. 从 `skills/5writing/templates/` 复制匹配模板到 `paper/`，保留模板所需的封面、摘要、页眉页脚和章节入口。
3. 建立图表规划：每张图对应一个章节、一个解释目的和一个真实文件。
4. 先写问题重述、数据理解、假设、符号和模型；再写结果与检验；最后写摘要、结论、模型评价和参考文献。
5. 把图表直接嵌入对应章节，在图表前后写清楚“为什么展示”和“从中得到什么”。
6. 运行 `6verity`，根据验收报告修正硬错误，再交付最终 PDF 和源文件。

## 论文内容门槛

- 摘要覆盖每个子问题的方法、模型和关键结果；摘要最后撰写。
- 每个模型都说明问题目标、变量、假设、目标函数、约束、求解方法和校验方式。
- 假设必须服务于模型，并在正文中被实际使用；关键歧义要说明选择理由。
- 数值只能来自结果报告、结果表或生成图表；统一小数位和单位，避免摘要与正文不一致。
- 预测必须报告合理的训练/验证或误差评估；优化必须验证可行性；评价必须解释指标方向、标准化和权重来源。
- 灵敏度分析要报告参数扰动与结果变化，不能只给定性判断。
- 参考文献必须真实可查，正文引用必须能对应文献条目。

## 输出边界

`paper/` 只呈现题目、方法、结果和结论。工作流文件名、内部 skill 名称、临时目录、代码路径和“待补充”等占位信息留在工作区报告中，不进入论文正文。

## 建议交付物

```text
paper/
├── main.tex 或 main.typ
├── sections/
├── references.tex 或 references.typ
└── main.pdf

reports/VERIFY_REPORT.md
```

验收未通过时，交付中必须明确列出未解决问题和影响范围；只有硬错误清零并完成必要编译检查后，才标记为可提交。
